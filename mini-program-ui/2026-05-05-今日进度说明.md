## 2. 海报页面进度

### 2.1 UI 和路径

用户反馈的问题：

- 点进海报页面后不知道下一步怎么做。
- 第二页仍然套大矩形，路径复杂。
- 大矩形里又有小矩形，视觉重复。
- 返回箭头、多层卡片、复杂入口让用户迷惑。
- 实际需求只是让用户先说清楚想做什么海报，缺什么再上传什么。

本次调整方向：

- 把海报页面改为对话式工作台，不再以复杂表单/卡片为主。
- 第一屏直接给用户一个明确引导，让用户说一句需求即可开始。
- 引导话术覆盖促销、节日祝福、通知、朋友圈转发等场景，不把海报限定成“卖什么”。
- 下方输入区保留文本输入、语音按钮、加号上传，交互逻辑更接近主流 AI 对话页面。
- 移除不必要的箭头和重复矩形感，减少层级。
- 底部按钮区域位置和视觉重新调整，避免过于靠上或显得单调。

涉及文件：

- `mini-program-ui/pages/poster/index.js`
- `mini-program-ui/pages/poster/index.wxml`
- `mini-program-ui/pages/poster/index.wxss`
- `lib/posters/intake.ts`
- `lib/posters/templates.ts`
- `app/api/mp/posters/intake/route.ts`

### 2.2 语音输入

用户反馈的问题：

- 语音输入时提示文字太浅，看不清。
- 用户在说话，气泡应在右侧，而不是左侧 AI 气泡。
- 按钮不是按住说话，松开后仍然保持录音状态。

本次调整：

- `touchstart` 开始录音。
- `touchend` 停止录音并发送。
- `touchmove` 上滑超过阈值触发取消。
- `touchcancel` 取消录音。
- 小于 800ms 的短录音会提示“说话时间太短”。
- 语音工作状态显示为用户侧右气泡，提升可读性。
- 录音按钮状态改为“按住说话 / 松开发送 / 松开取消 / 识别中”。

### 2.3 AI 需求收集

用户反馈的问题：

- AI 回复看起来每次都一样，不像真正调用模型。
- 收集信息的路径太机械。
- 做海报不一定是促销，也可能是节日祝福、老顾客维护、朋友圈转发等。

本次调整：

- 海报 intake 接口改为 DeepSeek 直接参与信息提取和追问。
- 普通 DeepSeek 响应更快，体验优先；Pro 路径不作为默认。
- 保留本地规则兜底，避免模型乱编店名、价格、日期。
- 对朋友圈、私域、社群、祝福、节日快乐、老顾客等场景强制归到 `P12` 轻分享/转发类模板。
- 当缺少“目标人群/适合对象”等字段时，即使模型说“信息够了”，接口也会改成明确追问缺项。

线上验证结果：

- 输入：`云朵咖啡，五一第二杯半价，5月1日到5月5日，想要松弛高级感，发朋友圈用`
  - 状态：200
  - 模板：`P12`
  - 缺项：`目标人群/适合对象`
  - 回复：`我先抓到「五一第二杯半价」。还差 目标人群/适合对象，你直接一句话补上就行。`

- 输入：`端午节祝福海报，给老顾客发，店名青禾养生，不卖东西，温暖一点`
  - 状态：200
  - 模板：`P12`
  - 缺项：无
  - 回复会让用户核对端午祝福方向。

性能记录：

- 普通 DeepSeek 多数请求约 4.6 到 6.7 秒。
- 刚部署后的冷启动/模型波动有一次约 18.9 秒。
- DeepSeek Pro 曾测到约 21 到 29 秒，不适合作为默认体验路径。

### 6.2 DeepSeek 直连

当前海报 intake 的模型选择逻辑：

- `POSTER_INTAKE_DEEPSEEK_MODEL`
- `DEEPSEEK_MODEL`
- 默认：`deepseek-chat`

当前海报 intake 的 key 选择逻辑：

- `POSTER_INTAKE_DEEPSEEK_API_KEY`
- `DEEPSEEK_API_KEY`

当前海报 intake 的 base URL 选择逻辑：

- `POSTER_INTAKE_DEEPSEEK_BASE_URL`
- `DEEPSEEK_BASE_URL`
- 默认：`https://api.deepseek.com/v1`

已实现保护：

- 模型只允许输出单个 JSON 对象。
- 店名、时间、价格、优惠等事实必须来自用户原文或已有资料。
- 如果模型输出无法 JSON 解析，会回到本地规则。
- 如果模型编造关键事实，会回到本地规则。
- 如果缺项未补齐但模型说“可以确认/可以生成”，会改用缺项追问话术。
